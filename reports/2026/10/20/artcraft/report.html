二、安装部署与使用指南

适用对象：终端创作者优先走 Windows/macOS 预编译安装路径；Linux 与源码构建属于开发者路径。

1. 终端用户安装（推荐路径）

  1. 打开 ArtCraft 官方下载页：https://getartcraft.com/，或在 GitHub Releases 下载最新构建：https://github.com/storytold/artcraft/releases。
  2. README 明确提供 Windows 与 macOS 的 stable releases；CI 也仅有 artcraft-macos-publish.yml 与 artcraft-windows-publish.yml 两条发布流水线。
  3. 下载对应平台安装包后按系统常规方式安装并启动。该路径不需要用户安装 Rust、Node、数据库或容器运行时。
  4. 首次使用建议从 Text to Image 开始：输入提示词，在应用内选择模型/提供方，先完成一次图像生成，再进入 Canvas、2D/3D 合成等进阶功能。
  5. 进阶功能可按 README 的功能表逐步使用：Image to Location、3D Image Compositing、2D Image Compositing、Image to 3D Mesh、Character Posing、Scene Blocking with Kitbashing、Character Identity Transfer、Background Removal、Image to Video 等。
  6. README 提供 两分钟 YouTube demo 与大量功能预览，可作为首次体验前的快速了解材料。

2. Linux 与源码构建路径

README 将 Linux 归入 Build from source，入口为 _docs/dev_setup.md。源码构建不是终端用户的一键安装路径，门槛明显更高：

  • 仓库是大型 Rust workspace，Cargo.toml 列出近 40 个 workspace 成员；前端为 Nx/React/Vite workspace。
  • 源码构建需要 Rust 工具链与 Node 环境；frontend/apps/artcraft/package.json 要求 node >=18.0.0。
  • Cargo.toml 注明 wreq 的原生前置条件：
  • macOS：brew install cmake pkg-config llvm
  • Windows：choco install cmake strawberryperl pkgconfiglite llvm nasm
  • 素材中未见 Dockerfile、docker-compose、Helm Chart 或 K8s 部署清单；该项目本身是桌面应用，不需要服务端容器化部署。

3. 首次使用建议

  • 先用 Text to Image 完成一次生成，建立“提示词 → 模型 → 结果”的基本闭环。
  • 再尝试 Prompted Image Editing / Canvas Image Editing / Image to Video。
  • 最后进入 2D/3D 合成、角色姿态与场景 Blocking 等高级 Crafting 功能。
  • 素材未提供可执行的 quickstart 脚本或示例项目；入门主要依赖 README 功能表、两分钟演示视频与应用内 GUI。

D2.1 产品设计与创新性（1.5 分）

打分: 1.2 / 1.5（7–8 档，80%）

  • 产品理念清晰：定位为面向艺术家、设计师、电影人的「intentional crafting engine」——不做单一模型聊天壳，而是把多模态生成（图/视频/音频/3D/Splat）嵌入专业创作工作流（分镜 Storyboard、情绪板 Moodboard、画布 PageDraw、3D 场景 PageScene、视频编辑器、角色库 Characters、图库 Gallery、帧提取器）。
  • 差异化明显：crates/api_clients/ 下并行接入 fal、Kinovi、GMICloud、Grok、Midjourney、OpenAI Sora、WorldLabs 等 14 套服务商，并在 artcraft_router 中做统一路由/参数归一（veo_3p1/build.rs、seedance_2p0/build.rs 等 600–850 行的 provider plan 逻辑），配合 browser_emulation、cloudflare_mitigation、cookie_store 直连消费级 Web 端点，属"聚合 + 深度工作流"的复合创新，不是简单复制。
  • 功能取舍得当但仍偏冗余：同时维护 Tauri（crates/desktop/artcraft）、纯 egui 原生（artcraft-native）、Web 前端三套壳，功能面极宽（keybinds、无障碍、任务队列、成本估算、双击确认），有 feature sprawl 迹象，但核心场景（提示词 → 参考素材 → 参数 → 入队 → 图库/时间线）闭环完整。
  • 扣分项：产品叙事仍偏"能力集合"，缺少统一的创作意图抽象；多个功能点（如 handlePromptedUpdate）明确标注为占位实现。

D2.2 架构设计与工程质量（2 分）

打分: 1.6 / 2（7–8 档，80%）

  • 宏观架构优秀：Cargo.toml workspace 明确按 api_clients/（每 provider 一 crate）、lib/（cookie_store、errors、filesys、jwt_light、http_headers 等细粒度工具 crate）、schema/public/enums（CommonModelType / InferenceModelType 受控词汇表）、desktop/、native/ 分层；前端 frontend/libs/ 按组件逐包拆分（每个组件有独立 README、@storyteller/ui-* 命名空间）；视频编辑器采用 Command + Facade + Manager（TimelineManager、AudioManager）与 Adapter 注入（VideoEditorAdapters）——这是相当专业的设计范式。
  • 解耦与抽象：TimelineManager 把 UI 操作全部翻译为可撤销命令；Scene/Editor 通过 SceneDeps 依赖注入刻意不引入 Zustand/Tauri；rpc 层用 trait 策略做计费（KinoviCostCalculatorTrait）。高内聚低耦合在子系统级成立。
  • 明显缺陷：文件级工程失控——gallery-modal.tsx 2,800+ 行、PaintSurface.tsx 2,000+ 行、TransformControls.js 单文件三类、PromptBoxVideo.tsx/Storyboard.tsx/ImagePromptRow.tsx 均 800–1,000+ 行；Backend、ArtcraftApp、Scene、Editor、PageSceneStore 均呈 God Object；InferenceModelType 与 CommonModelType 靠四处手工重复映射（to_str/from_str/serde rename/from_common_model_type）维持，靠测试兜底；index.ts barrel 导出面过大，易造成循环依赖与 tree-shaking 困难。
  • 复刻难度高：14 套第三方 provider 的逆向协议封装（含 TLS/UA 指纹模拟、Set-Cookie 会话解析、workflow.runTask tRPC 协议）、WASM 时间基（MediaTime）、de Casteljau 贝塞尔关键帧细分、Konva/Three.js 编辑器，构成真实技术护城河。
  • 代码量 482K 行对应功能广度基本匹配（未明显臃肿到不可维护，但已接近单人不可全览的规模）。

  • 扣分风险（真实存在）：代码中保留了 12 个第三方 provider 客户端，含 grok_consumer_client、midjourney_client、kinovi_web_client 等消费级订阅/cookie 复用实现。这意味着技术型用户可以绕过 ArtCraft 计费、直接使用自有消费订阅或自备 API Key（fal_client 等），对高阶用户构成明确的"免费平替"逃逸通道，削弱了单一付费触发点的强制性。

D4.4 增值服务空间与定价天花板

打分: 1.2 / 2（5–6 档，60%）

  • 增值方向明确：云渲染/长任务队列、团队素材库与版本管理、模型路由与成本优化（artcraft_router 已具备路由抽象）、企业内网私有化部署、SLA 与合规审计、场景/资产包市场抽成。
  • 收入扩展性良好：积分制天然是 per-usage，可随用户创作量线性增长，且能在同一体系内叠加 per-seat（团队版）与 enterprise flat fee。
  • 天花板受约束：当前可证据化的客单区间是专业消费者 $20–100/月（$240–1,200/年），与 Midjourney/Runway/Krea 同档；单客 $10K+/年的企业客单需要 SSO/审计/合规/专属支持等模块，而素材中（452 个开放 issue、4 名贡献者、无企业功能代码痕迹）均无对应支撑。
  • 毛利结构性隐忧：聚合器模式下推理成本占比高，若仅做"转售算力"则毛利被上游模型厂商压制；真正的溢价必须来自 crafting 层（3D 合成、角色一致性、镜头调度）——这也是 README 主打的差异化，但该溢价能否被客户认账仍待市场检验。

维度小结

ArtCraft 的商业模式在结构上是"开放客户端 + 封闭算力服务"的教科书式组合：MIT/Apache-2.0 双许可扫清了全部授权障碍，62 模型 / 5 家 provider 的统一接入与积分计费构成天然付费点，且转化逻辑（生成即付费）优于绝大多数开源工具类项目。核心不确定性集中在两处：一是 BYO-Key / 自带订阅带来的高阶用户逃逸，二是企业级上行空间缺乏产品化证据——项目尚处 v0.41.0、4 名贡献者的公司早期阶段，客单天花板目前只能锚定在专业消费者档位。综合判定为"良好"（8.0/10），变现结构优于同规模开源项目，但距离卓越（企业级 SaaS 叠乘）仍有明确缺口。

小结

ArtCraft 在竞争格局中占据一个真实且易于表述的差异化位置：「面向影视/美术的 AI 创作 IDE」——用 2D/3D 空间编排与机位、姿态、角色身份控制，把"提示词赌博"变成"可复现的工艺"，并横向聚合 62 个模型作为弹药库。33.8k Star 与密集发版证明这套叙事已被市场认可。
