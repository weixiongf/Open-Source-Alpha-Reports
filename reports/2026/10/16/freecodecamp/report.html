一、前置条件

项目 要求 依据
Node.js >=24 根 package.json → engines.node: ">=24"；各子包一致

二、推荐部署路径 A：Dev Container / Codespaces（最省事）

.devcontainer/docker-compose.yml 使用官方预构建镜像，可直接在 GitHub Codespaces 或本地 VS Code Dev Containers 打开：

name: freecodecamp-devcontainer
services:
  devcontainer:
    image: ghcr.io/freecodecamp/devcontainer:latest
    environment:
      GATSBY_HOST: 0.0.0.0
    volumes:
      - ..:/workspaces/freeCodeCamp:cached
    network_mode: service:db
    command: sleep infinity
    depends_on:
      db:
        condition: service_healthy
      setup:
        condition: service_completed_successfully
      mailpit:
        condition: service_started

该镜像（docker/devcontainer/Dockerfile）已预装 Node 24、pnpm、mongosh、gh，并预置依赖与构建缓存：

  • RUN pnpm install --frozen-lockfile
  • RUN pnpm turbo build --filter=@freecodecamp/shared
  • RUN pnpm turbo build --filter=@freecodecamp/curriculum
  • 仅通过 rsync 拷贝 .turbo 缓存到最终镜像，供运行时 pnpm install --prefer-offline 快速复用

三、推荐部署路径 B：本地裸机 + Compose 起基础设施

  1. 启动数据库与邮件服务（docker/docker-compose.yml 原文）：db（mongo:8.2，mongod --replSet rs0）、setup（rs.initiate(...) 初始化副本集）、mailpit（axllent/mailpit）。
  2. 安装依赖：pnpm install --frozen-lockfile（api 的 postinstall 自动执行 prisma generate）。
  3. 生成配置：仓库内提供的做法是 sample.env → .env（docker/devcontainer/Dockerfile 中 COPY sample.env .env）；client 侧另有 pnpm run create:env。
  4. 启动开发环境（根 package.json 脚本）： - 全栈：pnpm start（= turbo setup && npm-run-all -p develop:server serve:client） - 或分别启动：pnpm run develop:api（tsx watch --clear-screen=false src/server.ts）、pnpm run develop:client（gatsby develop --inspect=9230）
  5. 灌入演示数据：pnpm seed（内部串联 seed:surveys、seed:exams 与 demo user），需要认证用户时 pnpm seed:certified-user。
  6. 本地预览前端：cd ./client && pnpm run serve（gatsby serve -p 8000），访问 http://localhost:8000。
  7. 跑测试：pnpm test（turbo 全仓测试，共 371 个测试文件 / 58,452 行）。

四、关键注意事项

  • MongoDB 必须是副本集：compose 中 setup 服务专门执行 rs.initiate，普通单机 mongod 无法直接替换。
  • 邮件链路依赖 Mailpit：devcontainer 用 network_mode: service:db 共享网络命名空间，使 MONGOHQ_URL、MAILPIT_HOST 在 localhost 上可解析。
  • 首次构建耗时可观：client 为 Gatsby 站点，build 脚本使用 --max-old-space-size=7168，且 curriculum 需先构建出 curriculum/generated/curriculum.json。
  • 无示例工程：仓库中「示例」目录为 0，唯一可参考的“模板”是 curriculum/challenges/** 下的大量挑战 Markdown 内容文件。

维度结论

freeCodeCamp 面对的是一个真实、庞大且仍在增长的编程教育市场，痛点刚需明确，解决方案高度完整，且凭借 12 年积累的品牌与 45.7 万 Star 的社区效应形成强护城河。制约商业机会的核心不在需求侧，而在项目定位：它是 BSD-3-Clause 授权的非营利免费平台，收入依赖捐赠而非产品付费，代码与课程库本身不是为变现而设计，其「市场需求」与「可付费市场规模」之间存在天然鸿沟。

因此本维度评分中等偏上（7.0/10）：市场规模与痛点维度表现良好，市场时机（成熟红海）与场景广度（教育垂类）相对薄弱。若以该项目代码库为基础探索商业化，需明确区分「参考其技术架构/课程工程能力」与「直接商业化该平台」两条路径——后者与非营利定位冲突。

「外部市场数据缺失」已影响 D1.1 与 D1.3 的精确性，两条目均为量级估算，本维度整体置信度：低-中。
