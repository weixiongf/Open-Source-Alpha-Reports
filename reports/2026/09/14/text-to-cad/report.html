二、安装部署与使用指南

D9 上手难度等级：🟡 中等（面向有技术基础者） — 安装为一条命令，但运行依赖需 Python 3.11+ 环境与 agent 宿主；无容器化部署方案，部分 skill 依赖外部 CLI/硬件。以下几处关键步骤取自仓库原文（README / requirements.txt / pyproject.toml），未含基础环境搭建细节。

前置条件

  • Python 3.11+：packages/cadgen/pyproject.toml 中 requires-python = ">=3.11"
  • agent 宿主：Codex（需 0.142.0 或更新）/ Claude Code / Grok Build
  • npx：用于 Skills CLI 安装路径

安装方式

方式一：Skills CLI（README 标注的 preferred installation path）

npx skills add earthtojake/text-to-cad

README 说明：更新使用同一条命令（add 会重新拉取并覆盖已安装内容）；npx skills update 仅刷新 lockfile 中已存在的 skill，会漏掉新增 skill。移除某个 skill：

npx skills remove <skill>

方式二：Provider 原生插件

# Codex（requires Codex 0.142.0 or newer）
codex plugin marketplace add earthtojake/text-to-cad
codex plugin add cad@text-to-cad

# Claude Code
claude plugin marketplace add earthtojake/text-to-cad
claude plugin install cad@text-to-cad

# Grok Build
grok plugin install earthtojake/text-to-cad --trust
grok plugin enable cad

README 提示：新装的 skill 不出现时需重启 agent。

运行时依赖（各 skill 通过 requirements.txt 声明）

  • skills/cad/requirements.txt：cadgen[snapshot]==0.5.1
  • skills/cad-viewer/requirements.txt：cadgen==0.5.1
  • skills/dxf|sdf|srdf|urdf/requirements.txt：cadgen[snapshot]==0.5.1
  • skills/dfam-check/requirements.txt：trimesh、numpy、rtree、scipy、networkx、lxml
  • packages/cadgen 运行依赖：build123d、cadquery-ocp、ezdxf、shapely；snapshot extra 额外需 playwright（较大安装 + 浏览器下载）
  • CLI 入口：cadgen = "cadgen.cli:main"

部署注意

  • 无 Dockerfile / docker-compose / Helm（本地实测 has_dockerfile: false），仓库面向本地 agent 环境而非服务器编排部署。
  • G-code skill 依赖 "real slicer CLIs"；Bambu Labs 依赖本地打印机——这两类 skill 需额外的外部工具/硬件。
  • 仓库 models/（fixture corpus）以 LFS 指针形式下发，README 明确其 not needed to use the skills。

六、商业路径分析

基于 D4 识别的可行路径与 D5 的护城河结构，建议按以下优先级推进：

路径一（首选）：制造侧交易闭环 / 佣金

D4 已识别出真实的下游集成证据：SendCutSend（下单校验）、Bambu Labs（打印托管）。这是本项目最自然、与免费开源不冲突的变现点——技能本身免费，价值在「从模型到实物」的最后一公里。建议将下单校验、切片参数优化、打印队列托管做成付费增值层，按交易抽佣或订阅收费。该路径不触碰 MIT 协议边界，且直接强化 D5 所指的「制造侧闭环」防御工事。

路径二：企业版 / 私有化支持

对标客单价 $1K–10K/席/年（D4 定价天花板判断）。但必须先补齐 D7 指出的企业就绪短板：SSO/OAuth/LDAP、RBAC、审计日志、REST/OpenAPI 或 gRPC 接口、OTel/Prometheus 可观测性、健康检查端点。当前项目为单机工具，无分布式/高可用设计，横向扩展需引入任务分发层。企业版是天花板最高但前置投入最大的路径。

路径三：SaaS 托管（texttocad.dev）

当前 texttocad.dev 仅为文档站，viewer 明确为本地预览。托管化需要解决计算资源成本与几何内核授权问题，且与「本地部署」的核心卖点存在张力。建议作为中期选项，而非首发路径。

路径四：Open Core（cadgen 核心包）

技术上可行（MIT 允许），但 D4 明确指出「全部 skills 以 MIT 免费一次性分发，免费版近乎无功能阉割，付费触发点不自然」。若走此路，需重新设计功能边界，风险是引发社区反噬。

路径修正（依据价值画像）

作为 ⭐ 明星资产，必须同时经营社区声誉，避免竭泽而渔。参照 Elastic 改协议的反噬教训：本项目 15,574 Star 的势能来自 MIT 的完全开放承诺，任何收紧协议或对既有免费功能设墙的动作都可能摧毁分发优势。建议优先选择路径一（不改变开源边界），谨慎对待路径四。

分发位防御（D5 建议）

商业化应通过加厚制造侧闭环与跨平台分发位来强化防御，而非依赖单点算法。当前分发依赖 Codex/Claude Code/Grok 三方平台，建议主动拓展更多宿主 Agent 渠道，降低单一平台风险。
