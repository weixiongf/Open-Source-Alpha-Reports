一、项目概览

Better Harness（QoderAI/better-harness）是一个面向 AI 编程智能体的 Harness Engineering 平台——以「harness-as-code」为核心，支持定义 harness、运行受控实验、检视证据并比较结果，将编程智能体会话与项目证据转化为带证据边界的优先级改进项与组织级工程洞察。

  • 生命周期阶段：爆发期
  • 项目年龄：64 天（新项目）
  • 主语言：JavaScript（实际代码以 .ts 78,318 行、.rs 41,063 行、.tsx 19,076 行为主，总代码 143,229 行）
  • 许可：MIT License
  • 最新版本：v0.7.0-alpha2（2026-09-12）
  • 社区规模：2,323 Star / 186 Fork / 32 贡献者 / 近 30 天 267 commit
  • 宿主适配：10+ 编码智能体宿主（Claude Code、Codex、Qoder、Cursor、GitHub Copilot CLI、Qwen Code、Pi、Kimi Code、WorkBuddy、Grok）
  • 分发形态：宿主插件市场安装 / Qoder Desktop 内置零安装；npm 包 @qoder-ai/better-harness
  • 商业背景：由 QoderAI 公司主导，已内置进 Qoder Desktop（Quest 1.18.0+ 侧栏），形成「开源插件 → 商业 IDE 导流」的联动结构

项目处于 AI 编程智能体爆发早期，是 harness engineering 品类的先行者之一，产品理念（harness-as-code + 受控实验 + 证据驱动 + 多宿主适配）具真实创新与差异化，五维 Agent Work Loop 框架已清晰落地。

二、安装部署与使用指南

上手难度等级：🟢 简单（8.0/10） — 面向所有人，可提供详细操作步骤和命令。

Better Harness 不是需要自建服务器的服务端项目（仓库中无 Dockerfile / docker-compose / Helm Chart），其主交付形态是装进你已有的 Coding Agent 宿主的插件 + 一条报告提示词。因此"部署"等同于"向宿主注册插件市场并安装插件"，无数据库 / 缓存 / 消息队列等外部组件初始化。

二、安装（按宿主选择其一）

README 明确说明：Better Harness 不跨宿主使用统一入口，选你已在用的宿主照抄对应命令即可。

1. Claude Code

/plugin marketplace add QoderAI/better-harness

/plugin install better-harness@better-harness

验证（shell）：

claude plugin details better-harness@better-harness

详情中应出现 Skills (1) better-harness。

2. Codex Desktop 1. 打开 Settings > Plugins 2. 选择 + Add > From Marketplace 3. 填入 Git 仓库地址、设置 Git ref，Sparse paths 留空 4. 选择 Add marketplace，再从新市场里安装 Better Harness 5. 在待分析仓库中新建 task

使用 https://github.com/QoderAI/better-harness.git，Git ref 用 main。

3. Codex CLI

codex plugin marketplace add \
  'https://github.com/QoderAI/better-harness.git' \
  --ref main

codex plugin list --marketplace better-harness
codex plugin add better-harness@better-harness

README 特别提示：Codex 当前用 plugin add 与 --marketplace；plugin install / --source 属于另一套 CLI 契约。

4. Qoder Desktop（内置，零安装） - 会话入口：打开待分析仓库，新建 session 后运行报告提示词 - Quest 入口（Qoder 1.18.0+）：打开 Quest，从左侧栏选择 Better Harness (Beta)

5. Qoder CLI（Qoder Desktop 已安装时无需任何插件安装） 仅在没有 Qoder Desktop 时手动安装：

# Add the plugin marketplace source
qodercli plugin marketplace add 'https://github.com/QoderAI/better-harness.git'

# Install the plugin
qodercli plugin install better-harness@better-harness

# Check installation
qodercli plugin list

或从 git：

# Make sure directory exist
mkdir -p $HOME/.qoder/plugins/marketplaces/

git clone https://github.com/QoderAI/better-harness.git \
  $HOME/.qoder/plugins/marketplaces/better-harness --depth 1

qodercli plugin install $HOME/.qoder/plugins/marketplaces/better-harness

（Qoder CN 系列把 .qoder 换成 .qoder-cn。）

6. Cursor（README 明确：插件未发布到市场，安装计划被报告为 unavailable）

git clone https://github.com/QoderAI/better-harness.git
better-harness plugin plan install --host cursor --surface agent --scope session

7. GitHub Copilot

copilot plugin marketplace add QoderAI/better-harness
copilot plugin install better-harness@better-harness

copilot plugin list

8. 其他宿主 - Qwen Code：qwen extensions install QoderAI/better-harness - Pi：pi install <source> 或 pi -e <source> - Kimi Code：.kimi-plugin/plugin.json 插件安装 - WorkBuddy / Grok：见 Host Adapter Matrix

安装或更新插件后需要新开 session/task，宿主才会重新加载插件清单（README 明确提示）。

三、首次运行与验证

安装后在待分析仓库中直接运行报告提示词（自然语言，无需参数）：

  • Claude Code / Qoder：/better-harness analyze this project's AI coding workflow and generate an evidence-backed report
  • Codex Desktop：@better-harness analyze this project's AI coding workflow and generate an evidence-backed report
  • Codex CLI：$better-harness:better-harness analyze this project's AI coding workflow and generate an evidence-backed report

默认产物：Claude Code 在仓库的 .claude/better-harness 报告根目录下生成自包含 report.html + 配对 report.md + findings.json；Qoder 与 Cursor 产出宿主原生 Canvas 报告。也可要求内联输出、不落文件。

10 分钟跑通路径：Qoder Desktop 用户开箱即用（零安装）→ 新建 session → 粘贴提示词 → 出报告；其他宿主为「市场加仓库 → 安装插件 → 新开 session → 跑提示词」四步。

自查 / 生命周期命令（Beta，不接触注册表、不改宿主配置）：

better-harness plugin status --host all
better-harness doctor --platform all

better-harness plugin plan install --host qwen --surface cli --scope user
better-harness plugin verify --host qwen --surface cli

四、从源码开发 / 打包（可选，门槛明显更高）

要求 Node.js >=22.20.0 <25.0.0、npm >=10.9.3 <12.0.0，Windows/macOS/Linux：

npm ci
npm test
npm run pack:verify

构建源码本地 Codex 插件产物（输出到 dist/plugins/better-harness）：

node scripts/packaging/build-host-plugin.mjs

不读本地 session、仅检查仓库证据：

node scripts/better-harness.mjs report --no-sessions

本地预览内置 fixture：

npm run preview -- --open

npm run preview 默认监听 127.0.0.1，是本地检查工具而非鉴权分享服务；Canvas 预览还需已安装的 Qoder runtime 或显式 --sdk-media / --sdk-root 路径。

D2.1 产品设计与创新性

打分: 1.2 / 1.5（7–8 档，80%）

项目定位为「编码 Agent 的 Harness 工程平台」，核心理念是把 Agent 工作流当作可工程化的对象：以 DSL 声明 harness、运行受控实验、检视证据、对比结果。这一「harness-as-code + 受控实验 + 证据驱动」的产品思路在同类 Agent 工具中具有明显差异化——多数项目停留在「跑一个 Agent」，而本项目试图把 Agent 行为变为可测量、可复现、可对比的工程资产。

  • 产品理念清晰：README/docs/concepts.md/docs/docs/concepts/agent-work-loop.md 明确给出「Agent Work Loop」五维评估框架（任务理解/受控执行/变更验证/可靠交付/学习捕获），并在 docs/src/pages/index.js 以数据驱动方式呈现，理念落地。
  • 功能围绕核心场景：定义（DSL 编译）→ 执行（多宿主适配器）→ 实验对比（baseline vs candidate）→ 证据检视（Inspector/Evidence Host）→ 组织洞察，链路完整。
  • 差异化：多宿主适配（Claude Code/Codex/Qoder/Cursor/Copilot/Qwen/Pi/Kimi/WorkBuddy/Grok 等 10 个 host）、docs/docs/hosts/adapter-matrix.md 适配矩阵、可对比实验与证据边界（TaskLoopEvidenceBoundary）构成独到取舍。
  • 扣分点：产品仍在 alpha 早期，创新理念尚未经完整商业闭环验证；部分功能（组织级洞察）尚在 roadmap。

依据：README/描述、docs/ 概念与设计文档、ADRs、docs/src/pages/index.js 的宿主/维度数据结构。

打分: 1.6 / 2（7–8 档，80%）

  • 版权归属：不集中。32 名贡献者各自持有其贡献版权，无 CLA 意味着无法单方面变更许可（如未来切换双许可/商业许可）。这一点对"开源核心 + 商业授权"的双协议变现路径构成实质约束，是该项目在 D4/D6 交叉处的主要法律短板。不过项目本身为 MIT，无 copyleft 义务，变更许可的需求强度不高。

结论

Better Harness 在许可证本体上几乎无法律硬伤：全仓库统一 MIT、SPDX 声明规范、不含任何商业限制性附加条款、依赖链未见 GPL/AGPL 传染，也未发现侵权诉讼类信号。同时，贡献流程治理（COC + CODEOWNERS + PR 模板 + inbound 许可声明）齐备，优于多数同规模开源项目。

主要风险敞口有三点，均不构成"阻断式"障碍，但会在商业尽调中被提出：

  1. 商标与专利未经核查（D6.3 置信度低），且仓库无商标使用政策，品牌资产的法律边界未划定；
  2. 无正式 CLA，版权分散于 32 名贡献者，若未来需要双协议授权或专利再许可，需回溯取得贡献者同意；
  3. 内嵌与未披露依赖（Apache-2.0 分发归属、boxlite/agent-client-protocol/@homology/* 许可证待补审）需要一次第三方依赖清单（SBOM/NOTICES）梳理。

综合加权：D6 =（2.4 + 2.0 + 1.5 + 1.6）/ 10 = 7.5 / 10，处于「良好」区间下沿——协议层风险低，风险集中在需人工补做的商标/专利核查与贡献者版权集中化，属可管理范围。

维度结论

  • 优势：安全编码细节（脱敏、路径围栏、同源防护、TOCTOU 校验）与 CI 覆盖（3 OS × 3 语言栈）明显优于同阶段项目；集成面（多宿主适配 + ACP 协议）是差异化能力。

  • 定性: 该维度整体为"一般（5–6 档）"——作为开发者工具定位合理，但距离企业级平台运营要求仍有系统性差距。

Better Harness 的使用价值画像是典型的「高免费完整度 + 中低效用强度 + 规模尚未形成」：
