1.3 一句话定位

Chrome DevTools MCP 是一个由 Google ChromeDevTools 官方团队维护的 MCP 服务器，适用于 AI 编码代理生态，主要面向使用 Claude/Cursor/Copilot 等 Agent 的开发者，用于将 Chrome 浏览器的调试、性能分析与自动化控制能力无缝接入 AI 编码工作流，使 Agent 能够直接操作真实浏览器完成端到端调试任务。

二、安装部署与使用指南

环境要求

  • Node.js LTS（^20.19.0 || ^22.12.0 || >=23）
  • Chrome 当前稳定版或更新（官方仅保证 Google Chrome 与 Chrome for Testing 的兼容性）
  • npm

快速开始（MCP 模式）

在 MCP 客户端配置中添加以下内容：

{
  "mcpServers": {
    "chrome-devtools": {
      "command": "npx",
      "args": ["-y", "chrome-devtools-mcp@latest"]
    }
  }
}

仅需浏览器基础能力时，可使用 --slim 瘦身模式：

{
  "mcpServers": {
    "chrome-devtools": {
      "command": "npx",
      "args": ["-y", "chrome-devtools-mcp@latest", "--slim", "--headless"]
    }
  }
}

各编辑器/Agent（Antigravity、Claude Code、Cursor、VS Code 等）的具体配置入口见 Client Configurations Guide。

首次验证

配置完成后，在 MCP 客户端中输入：

Check the performance of https://developers.chrome.com

若一切正常，客户端将自动打开浏览器并录制一段性能 trace。注意：MCP server 连接本身不会自动启动浏览器，浏览器会在首个需要浏览器实例的工具调用时自动拉起。

关键可选参数

  • --headless：无头模式
  • --slim：精简工具集，仅保留基础浏览器任务
  • --isolated：隔离的用户数据目录
  • --no-usage-statistics：关闭默认启用的使用统计收集（等价环境变量 CHROME_DEVTOOLS_MCP_NO_USAGE_STATISTICS 或 CI）
  • --no-performance-crux：关闭向 Google CrUX API 发送 trace URL 以获取真实用户体验数据

更多参数及 WebSocket 连接配置见 Configuration Guide，故障排查见 Troubleshooting。

D1.2 痛点真实性与解决程度：2.0 / 2.5

核心结论：解决的是 AI 编码代理“看不见浏览器”的关键痛点，方案完整，体验显著优于自建方案。

  • 痛点真实性：编码代理若要改动 Web 应用、复现 bug、验证交互、定位性能问题，必须像人类开发者一样实时控制浏览器并读取运行时状态。若缺少这一层，Agent 只能依赖静态代码理解，容易出现“代码正确但页面错误”的根本盲区。这种“非用不可”的性质与浏览器自动化测试的历史刚需一致，同时被 AI Agent 的可信执行需求放大。
  • 解决完整度：项目不是简单的 CDP 封装，而是将 Chrome DevTools 工程能力输出为 MCP tool 集，包括性能 trace、网络请求分析、页面截图、console 消息及 source-map 错误栈；并提供 --slim、--headless、--isolated、Android 调试、Chrome for Testing 等细分模式。仓库内含约 10.7 万行 TypeScript/JavaScript 代码、25 个文档文件和多个专项 skills（LCP、a11y、memory leak、cookie 调试），属于完整可落地的工程级方案。
  • 替代成本：替代方案包括 Playwright MCP、Puppeteer 手写 Agent 桥接、或直接暴露 CDP endpoint。它们在单纯驱动动作层面可用，但在 DevTools 深度的 trace 分析与前端性能诊断上体验显著更弱或需要大量二次开发。作为 Chrome DevTools 官方团队项目，其替代成本较高。
