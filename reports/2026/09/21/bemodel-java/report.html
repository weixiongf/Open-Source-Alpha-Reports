D2.1 产品设计与创新性（1.2 / 1.5） 产品理念清晰且具备独立主张：以「本体驱动 AI」为核心，用本体概念/关系/公理作为语义约束层，构建「AI+本体」与「AI 直连数据库」「人工固定页面」的三臂对比实验（lab/、LabRunService），试图量化本体带来的确定性增益，而非盲目包装 LLM。功能设计围绕核心场景收敛：本体建模→映射→语义问答（Ontology2SQL）→客服/RCA 根因分析→数据治理→增长回路（miss→AI 提案→人工裁决）。差异化点明确：证据链「五段式」（结论→路径→锚点→动作→参考，TraceService 硬约束「无锚点不输出」）、发布前确定性自检（OntologyCheckService 三色 DFS 找继承环）、术语分叉/口径漂移扫描（DriftService）、推演仿真（SimulationService+PropagationEngine）。创新性属真实设计创新而非简单复制。不足在于产品偏「演示/样板」导向（DataSeeder 造数、沙箱库、三臂剧本），离成型商业产品的取舍尚需收敛。综合落在 7–8 档。

D2.2 架构设计与工程质量（1.6 / 2.0） 架构按领域清晰分层：ontology / datasource / clinical / cs / rca / lab / simulation / flow / governance / link / impact / value / trace / mcp / rdf / search / auth，Server（Spring Boot + MyBatis-Plus ServiceImpl）与 Web（Vue 3 组合式 + Pinia）分离。模式运用一致且恰当：状态机（概念/规则/映射生命周期 TRANSITIONS/LIFECYCLE）、模板方法（run/buildPayload 唯一出口）、策略/分发（8 个 QC 规则解释器、探针分派）、注册表（LabExperimentRegistry、SimulationScenarioRegistry）、事件驱动缓存失效（MappingChangedEvent）。存在真实工程深度：Jena 解析 OWL/RDF 投影本体（OwlImportService）、传递闭包物化与有界 BFS（ReleaseService.closureBfs，深度 12 截断）、SHACL 验证、传播引擎、BFS 追溯（walkChain/traverseStep）。复刻难度高（本体推理 + 医疗领域 + AI 编排 + 图算法），构成一定技术护城河，代码量与功能复杂度大致匹配（39.2K 行 / 307 文件）。但技术债明显：DataSeeder 单文件 1000+ 行、FlowService.loop 单方法 >200 行、QcRuleEngine 单类承载 8 种解释器、多处 @SuppressWarnings("unchecked") 强转反映类型不安全、ConceptService.ancestorsOf / GovService.tables 存在 N+1、部分 LIMIT/OFFSET/IN 用字符串拼接。综合 7–8 档偏下沿。
