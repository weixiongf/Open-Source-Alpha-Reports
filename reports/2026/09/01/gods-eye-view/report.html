D2.2 架构设计与工程质量（2 分）—— 1.8 分

判断依据：整体架构采用模块化单例 + 分层设计，src/data/ 下每个数据源一个独立图层模块（flights、satellites、cctv、militaryFlights、traffic、aisLiveVessels 等），统一实现 enable/disable/update/destroy 生命周期接口，data/manager.js 负责注册、调度和状态同步，解耦充分。共享基础设施抽离到位：worldOverlay.js（屏幕空间标签渲染调度器）、worldOverlayDraw.js（纯几何绘制层）、labelArbiter.js（标签仲裁）、renderGovernor.js（渲染治理）、contextStore.js（上下文存储）、groundFloor.js（地面高度钳制）。每个模块内部大量使用对象池、LRU 缓存、空间哈希、TypedArray 位打包、帧戳替代 Map.clear、单飞批量请求等高性能算法，工程积累量极大。复刻难度很高——涉及 Cesium 3D 引擎深度定制、SGP4 轨道传播、Douglas-Peucker 几何简化、死推算运动模型、WebRTC 语音实时交互、多级 LOD 调度、地理空间数学（ENU 帧、MGRS、EGM96 大地水准面）等跨领域知识。目录规范，命名一致（xxxLayer、xxxPolicy、xxxRegistry）。主要扣分点：部分核心文件超大（ui.js ~10000 行、vite.config.js ~7000+ 行、flights.js ~5000+ 行），职责过度集中，已出现技术债苗头；vite.config.js 同时承担 15+ API 代理、缓存、认证、速率限制，属于典型的"上帝对象"。

  • 付费意愿强度：目标客户（政府/军方承包商、企业安全/情报团队、GEOINT 从业者）预算充足，付费能力强；但当前 14.5K stars 的社区主体是爱好者/技术用户，付费转化漏斗顶端质量有待验证。
  • 转化漏斗自然度：当前闭环缺失——repo 内无企业版入口、无定价、无联系方式 CTA；转化路径是间接的（用户自行发现 halfpixel.ai）。升级触发点逻辑成立但衔接不自然，处于"用户用爽了但不知道去哪付钱"的状态，按 5–6 档评分。

D4.4 增值服务空间与定价天花板（1.6/2.0）

  • 增值空间（明确且多层次）： 1. 历史数据回放/时间切片（作者亲自点题，定价天花板最高）； 2. 企业数据源接入（SAR、商业 AIS、premium imagery——README 列为 enterprise contracts）； 3. 部署与合规扩展（私有化、SSO/权限、审计日志、SLA）； 4. 行业解决方案（港口监测、边境态势、能源基础设施巡检）。
  • 定价天花板：GEOINT/OSINT 领域企业软件客单价普遍可达 $10K+/年（参照 Palantir、Maxar、Planet 的数据交付模式）；单个政府合同或达 $100K+ 量级。但项目作为"viewer"而非"data provider"，直接定价受制于上游数据成本，需通过增值服务（历史回放、集成）抬升客单价。
  • 收入扩展性：可从业余爱好者捐赠（≈$0）→ 专业个人订阅（$99–299/年）→ 企业 flat fee（$10K+/年）→ 按 usage 计费的大客户合同逐级扩展，扩展路径完整。
  • 结论：增值方向明确、天花板高，符合 7–8 档；尚未有实际定价验证，不取更高档。

综合结论与风险提示

总体评价：God's Eye View 在商业模式维度呈现"高潜力、低落地"的特征。MIT 协议 + 高影响力作者 + 有实体商业承接（halfpixel.ai）+ 明确的 enterprise feeds 天花板认知，构成了优于多数开源项目的先天商业条件（7.9/10）。当前最关键的扣分项集中在转化闭环缺失：没有企业版、没有定价、没有销售入口——一切停留在"潜力"而非"业务"。

三大关键风险： 1. 数据合规风险（最紧迫）：TeleGeography 海底电缆等捆绑数据为 CC BY-NC-SA，任何商业版本必须先做数据集清洗或商用授权，否则构成授权违约； 2. API 依赖风险：核心体验依赖 OpenSky、Google Maps、OpenAI 等第三方 API，商业版本的边际成本受上游定价制约，需代理/缓存架构摊薄（项目已有 budget-governed proxies 雏形）； 3. 工程成熟度风险：0 行测试、2 名贡献者、v0.1.0 首发，开源版距"企业可部署"尚有显著工程化距离，付费产品的开发周期可能长于预期。

一句话结论：商业模式设计方向正确、变现天花板高，是典型的"开源品牌 + 商业数据服务"打法；但当前处于极早期，付费闭环与产品化是通向收入的确定性瓶颈——建议以 D4.2 的 enterprise feeds 方向（历史回放 + 企业数据接入）作为商业化突破口优先验证。
