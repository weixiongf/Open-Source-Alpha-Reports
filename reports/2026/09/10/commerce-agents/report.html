二、安装部署与使用指南

上手难度等级：🟡 中等（D9 = 7.0 / 10，面向有技术基础者）。以下仅列出关键步骤与要点，基础环境操作（虚拟环境、npm 用法等）从略。

1. 环境前置要求

  • Python 3.11+（所有 pyproject 均声明 requires-python = ">=3.11"）
  • Node 22（README Quick start 明确要求）
  • ANTHROPIC_API_KEY（必须自备 Claude API Key，否则 demo 无法运行）
  • 无需数据库 / 缓存 / 消息队列等外部服务；示例后端为仓库内自包含实现

2. 运行官方 Demo（推荐首次验证路径）

README 给出的完整命令（原样照抄）：

git clone https://github.com/anthropics/commerce-agents.git && cd commerce-agents
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt       # the seven packages and their pinned dependencies
cp .env.example .env                  # add ANTHROPIC_API_KEY
(cd examples && npm ci)               # the eight web apps share one workspace
python scripts/run_demo.py retail     # API :8000 + storefront :3000

要点：

  • requirements.txt 中 7 个本地包以 -e ./... 可编辑方式安装，其包名在 PyPI 上未注册、且兄弟依赖被钉在索引上不存在的版本，因此必须整仓克隆后从目录安装，不能单独 pip install 某一个包。
  • scripts/install.sh 内部即执行 pip install -r requirements.txt 这一行。
  • 端口分配：retail（storefront :3000，portal :3100）、travel（:3001 / :3101）、telecom（:3002 / :3102）、entertainment（:3003 / :3103）。
  • 启动参数：--merchant 只起商户门户，--all 两者都起。

3. 其他三种运行方式（按需选一）

# Agent SDK 运行时（单轮对话 / 交互式审批）
python shopping-agent/runtime-agent-sdk/main.py --once "a two-person tent under $250"
python merchant-agent/runtime-agent-sdk/main.py          # approves staged changes with y/N

# Managed Agents 托管部署（默认 dry run，--live 才真部署）
scripts/deploy_managed_agent.sh shopping-agent/managed-agents/shopping-agent   # 或 merchant-agent/...

4. 基于脚手架构建自己的 Agent

claude plugin marketplace add anthropics/commerce-agents
claude plugin install commerce-builder@claude-commerce-agents
claude
/scaffold-commerce-agent a shopping assistant for our store

后续命令：/add-commerce-flow、/author-commerce-evals、/review-commerce-agent。

5. 验证与自检

ruff check . && ruff format --check . && pytest && python scripts/check.py
python scripts/verify_all.py                        # 上述内容 + 部署 dry run + Web 构建
python scripts/smoke_chat.py --vertical travel      # 一次真实对话；需要 Key

6. 部署方案要点（生产化需自行补齐）

  • 本项目不提供 Dockerfile / docker-compose / Helm Chart，容器化与编排需自行构建。
  • 官方部署路径为 Claude Managed Agents（scripts/deploy_managed_agent.sh，默认 dry run）；docs/deployment.md 覆盖 GCP Vertex AI、AWS Bedrock、Microsoft Foundry 与网关接入。
  • 接入自有系统需实现 StorefrontBackend / MerchantBackend 接口；docs/backends.md 给出身份与凭证、有序流程、结账等映射指引。
  • 示例无鉴权，MCP Server 绑定回环地址，不应直接暴露公网。
  • 注意定位：README 声明 this is a reference implementation; it is not maintained and does not accept contributions.

结论

需求侧成立且时机有利，但「项目自身」与「市场机会」之间存在明显断层。

  • 利好：商务智能体是 2026 年企业 AI 落地最明确的场景之一，零售/旅游/电信/娱乐四个垂直面的示范覆盖了广度，Anthropic 的品牌与「安全护栏 + 审批门禁 + 三运行时」的工程深度，使其在同类参考实现中具备稀缺性；2,614 star、466 fork 显示需求侧关注度真实（创建当天即获此热度）。
  • 风险：项目定位是参考蓝图而非产品——无鉴权、数据虚构、"not maintained and does not accept contributions"、单贡献者、无 Release、90 天 0 个 Issue 关闭。它本身不构成可独立变现的资产，其商业价值主要体现在为 Anthropic API/托管智能体引流（变现距离远，归属于后续维度评估）。
  • 置信度声明：本维度未获取到外部市场规模/竞品数据，D1.1 的市场量级与 D1.3 的竞争密度均为基于项目类型与行业类别的定性估算，置信度低。

逐项判断依据

D2.1 产品设计与创新性 — 1.2 / 1.5（80%）

  • 产品理念清晰：以「购物 Agent（消费者侧）+ 商户 Agent（商家侧）」双主体覆盖电商价值链两端，并以 retail / telecom / entertainment / travel 四个垂直领域示例验证通用性，README 明确定位为「reference blueprint」，边界与目标一致。
  • 功能设计围绕核心场景：shopping-agent 覆盖搜索发现、购买研究、结账、客户关怀、记忆个性化；merchant-agent 覆盖目录、定价促销、库存运营、营销活动、业绩洞察，并配有对应 skills/*/SKILL.md。
  • 创新性明显：设计上有若干非通用做法——① 变更门控（propose → preview → approve → apply，StagedChange/ChangeLedger，暂存不触碰实时状态）；② 输出接地与幻觉抑制（enrichment.py 将模型给出的 metric pick 解析回本次会话工具真正返回的数据，PresentationRefused 拒绝无依据内容）；③ 溯源与权限门控（approved_change_ids、host_action_change_ids、操作员身份由宿主认证派生，模型无法伪造归因）；④ 工具列表固定顺序构建以换取请求字节一致与提示缓存确定性。
  • 差异化：相比一般 Agent demo，本项目在「护栏 / 接地 / 溯源」上的工程投入显著，且以 plugins/commerce-builder（Claude Code 插件命令与技能）形式交付开发者工作流。
  • 未给满分原因：本质仍是参考实现而非可售卖产品，示例数据大量为虚构 fixture，缺面向生产的可配置化（多处硬编码 demo 账户/默认值）。

D2.2 架构设计与工程质量 — 1.6 / 2（80%）

  • 分层清晰：commerce-common（共享领域/执行/记忆/流式/围栏）为核心底座；shopping-agent、merchant-agent 各自分层为 core（领域模型+接口+工具契约）、runtime-messages-api（Messages API 编排器）、runtime-agent-sdk（SDK 运行时）、managed-agents（MCP server / 定时摘要）、skills；examples/* 由 api（FastAPI mock 后端）、storefront-web、merchant-web、demo_common（共享 fixture）、web-shared（共享 React 组件库）构成。目录结构规范、命名一致。
  • 解耦与抽象得当：StorefrontBackend / MerchantBackend 以 ABC/Protocol 定义契约，示例后端以适配器接入；工具执行器 BaseToolExecutor 提供统一框架，PresentationExtension / DelegateExtension 为扩展点，MemoryStore 为 Protocol 且有 InMemory/JsonFile/Retention 三种实现（装饰器包装）。
  • 可复用性高：commerce-common 抽出执行、记忆、围栏、流式协议、prompt 组装、测试假件（testing.py 提供 FakeClient/FakeStream/SpyStore），垂直示例共享 demo_common 与 web-shared。

  • 扣分原因：shopping-agent 与 merchant-agent 的 prompt / executor / orchestrator / registry 呈镜像重复（同构但各自维护），存在结构性重复；示例内硬编码较多；单仓 66,990 行对参考项目偏大。

D2.4 安全性 — 0.8 / 1（80%）
