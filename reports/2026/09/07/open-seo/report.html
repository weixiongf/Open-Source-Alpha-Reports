二、安装部署与使用指南

上手难度等级: 🟡 中等（有技术基础者）

OpenSEO 提供 Docker（本地体验推荐） 与 Cloudflare（公网自托管推荐） 两条自托管路径。无论哪条路径，都需要 DataForSEO API key 才能获取 SEO 数据。非技术用户建议优先使用官方托管版（openseo.so 免费试用）。以下为关键步骤概览：

前置条件

  • DataForSEO API key: 必需。所有 SEO 数据均通过 DataForSEO API 获取，需自行注册并支付数据费用（参见 docs/DATAFORSEO_API_KEY.md）。
  • Docker 路径: 需安装 Docker。
  • Cloudflare 路径: 需拥有 Cloudflare 账号（免费计划可用），并准备 CLOUDFLARE_API_TOKEN 等凭据。

方案 A: Docker（本地快速体验）

  1. 参照 docs/SELF_HOSTING_DOCKER.md 获取 Docker 运行配置。
  2. 配置环境变量，核心必填项为 DATAFORSEO_API_KEY（Base64 编码的 login:password）。
  3. 启动容器后通过浏览器访问本地端口，按界面引导连接你的域名。

注: 仓库根目录未提供 Dockerfile / docker-compose.yml（素材未收录），构建镜像需基于项目源码与 SELF_HOSTING_DOCKER.md 文档指引操作。项目作者提示"除非你已在自托管其他应用且有信心，否则推荐 Cloudflare 方案"。

方案 B: Cloudflare（推荐公网使用）

  1. 参照 docs/SELF_HOSTING_CLOUDFLARE.md 完成 Workers/D1/KV 等资源创建。
  2. 安装依赖并执行部署命令（部署脚本示例，来自 package.json）:

```sh # 安装依赖（项目使用 pnpm@10.30.1） pnpm install

# 生产数据库迁移（D1） npm run db:migrate:prod

# 构建并部署到 Cloudflare Workers npm run deploy ```

  1. 设置 Cloudflare bindings 环境变量，包括: - DATAFORSEO_API_KEY: DataForSEO API 访问凭据（Base64 编码 login:password） - AUTH_MODE: 认证模式（cloudflare_access 或 local_noauth） - OAUTH_KV: MCP 客户端注册/授权使用的 KV namespace

配置要点

  • API Key: 将 DataForSEO 的 login:password 进行 Base64 编码后填入 DATAFORSEO_API_KEY。
  • 认证模式: 本地信任环境可用 local_noauth，公网部署必须配置 Cloudflare Access。
  • 数据库: Cloudflare 路径使用 D1（SQLite），亦支持 PostgreSQL（参见 docs/LOCAL_POSTGRES.md 与部署脚本 deploy:postgres）。

首次使用路径

  1. 打开 Web 界面 → 创建 Project → 添加你的域名。
  2. 在界面中连接 Google Search Console（参见 docs/SELF_HOSTING_GOOGLE_SEARCH_CONSOLE.md）。
  3. 核心 SEO 工作流（关键词研究、排名追踪、外链分析、网站审计等）均可通过界面直接操作；AI Agent 用户可进一步配置 OpenSEO MCP 与 Agent Skills，使用 npx skills add every-app/open-seo --skill <skill-name> 添加预置技能。

评估概述

OpenSEO 定位为 Semrush/Ahrefs 的开源替代品，项目自 2026 年 2 月创建以来以极高频率迭代（6 个月内发布 30+ 个版本，90 天合并 171 个 PR），已形成覆盖关键词研究、站点审计、排名追踪、外链分析、GSC/GA4 集成的完整产品矩阵。其最大的差异化设计在于将全量 SEO 能力以 MCP（Model Context Protocol）工具形式开放，使 Claude、Codex 等 AI 代理可直接调用，这是一条与传统 SEO SaaS 截然不同的产品路径，体现了显著的模式创新。项目当前处于 v0.1.x 阶段，尚未发布 1.0 正式版，商业化成熟度仍有提升空间。

关键发现

  1. D2.2 架构质量是最大护城河：基于 Cloudflare Workers 原生能力（Workflows 分阶段审计、Durable Object Scratchpad、Hyperdrive 连接池）构建的分布式架构，配以 CAS 并发控制、幂等写入、分片处理等工程实践，复刻门槛极高（预计 20+ 人年）。此架构直接支撑了审计、排名追踪等重任务的 SaaS 级稳定性。

  2. 安全实践达到生产级标准：OAuth 授权服务器实现（PKCE、HMAC state、令牌加密）与多云密钥管理（Config.redacted 部署为 secret_text）均已达到商业 SaaS 水准，为商业化交付提供了信任基础。

  3. 核心成熟度短板是版本阶段：项目仍处 v0.1.x，多项文档提及"测试版/尚不支持"，且 149 个开放 Issue 中 bug 处理率（90 天关闭 34 个 vs 创建 171 个 PR）显示维护速度追不上需求速度。此外运行环境深度锁定 Cloudflare 生态、无 i18n 支持，可能制约更广泛的自托管与企业采用。

  4. 测试体系可信但覆盖率无门禁：审计引擎的 fixture 回归测试、GA4/GSC 等外部 API 集成测试体现了针对性质量投入；但未发现覆盖率阈值卡点与独立依赖安全扫描，在 CI 中增加覆盖率报告与工具链部署可进一步提升质量保障闭环。

结论

OpenSEO 是一款产品设计与工程质量均属上乘的开源 SEO 平台。其在 D2.2（架构与工程质量）、D2.4（安全性）上达到商业级水准；产品理念创新（MCP + AI Agent）洞见了 SEO 工具从 GUI 交互到 Agent 调用迁移的行业趋势。主要限制在于尚未发布 1.0 稳定版、深度绑定 Cloudflare 生态以及 i18n/无障碍等国际化与可访问性准备不足——考虑到项目创建仅 6 个月便有此成熟度，这些短板预计将随 Roadmap 推进快速补齐。综合得分 9.15 分，在当前阶段已具备支撑技术验证型商业化的能力，但距离大规模企业级交付仍有一定距离。
