二、安装部署与使用指南

1. 安装方式

Hermes Agent 官方提供两种主流的一键安装通道，安装器自行处理全部依赖（uv、Python 3.11、Node.js、ripgrep、ffmpeg，以及 Windows 下的便携版 Git Bash），无需用户手动安装系统级依赖。

Linux / macOS / WSL2 / Termux（单行命令）：

curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash

Windows 原生（PowerShell）：

iex (irm https://hermes-agent.nousresearch.com/install.ps1)

安装完成后：

source ~/.bashrc    # reload shell (or: source ~/.zshrc)
hermes              # start chatting!

官方同时提供 Docker 镜像与 Nix 两种分发方式。注意：pip/PyPI 与 Homebrew 已不再是受支持的安装通道——setup.py 中明确设置了构建守卫，在非 Nix 环境下执行 wheel/sdist 构建会直接报错，因此普通用户应优先走官方安装器或 Docker。

2. 首次使用与配置

安装后通过交互式向导完成首次配置，不需要手写配置文件：

hermes              # Interactive CLI — start a conversation
hermes model        # Choose your LLM provider and model
hermes tools        # Configure which tools are enabled
hermes config set   # Set individual config values
hermes config get   # Print individual config values
hermes gateway      # Start the messaging gateway (Telegram, Discord, etc.)
hermes setup        # Run the full setup wizard (configures everything at once)
hermes claw migrate # Migrate from OpenClaw (if coming from OpenClaw)
hermes update       # Update to the latest version
hermes doctor       # Diagnose any issues

若不想逐个收集各工具 API Key，可用 Nous Portal 一站式完成：

hermes setup --portal

该命令通过 OAuth 登录、将 Nous 设为 provider 并开启 Tool Gateway，一条命令完成全部初始配置。

3. Docker 部署

仓库根目录提供 docker-compose.yml，包含 gateway 与 dashboard 两个服务，数据卷挂载 ~/.hermes:/opt/data，默认 network_mode: host。按文件头注释使用：

HERMES_UID=$(id -u) HERMES_GID=$(id -g) docker compose up -d

HERMES_UID / HERMES_GID 用于将容器内 hermes 用户重映射为宿主机用户，保证数据卷文件读写权限一致（不设置时默认 10000）。Dashboard 默认只绑定 127.0.0.1（command: ["dashboard", "--host", "127.0.0.1", "--no-open"]），远程访问需使用 SSH 隧道或自行加反向代理鉴权，不应直接暴露 0.0.0.0。

4. 快速验证路径

官方文档 Quickstart 给出的路径为「Install → setup → first conversation in 2 minutes」。全新安装后执行 hermes 进入交互 CLI，或执行 hermes setup --portal 完成 provider 配置后即可开始对话。消息网关场景则执行 hermes gateway setup + hermes gateway start。

D2.1 产品设计与创新性（1.2 / 1.5 分）

产品理念：项目定位为 "The agent that grows with you"（自我改进 AI 代理），核心主张是从经验中生成技能、使用中持续改进技能、并在任何环境运行。这一"成长型代理"理念在同类项目中差异化显著。

功能设计：功能围绕"自我改进"核心场景展开——技能生成与索引（skills/ + optional-skills/ 20+ 类目）、记忆系统（多种 MemoryProvider，含 OpenViking 等）、上下文压缩（context_compressor）、15+ 平台网关适配（Telegram/Discord/Slack/Matrix/飞书/QQ 等）、cron 定时任务、浏览器自动化等。信息架构合理，功能与核心场景关联紧密。但 60+ 个 optional-mcps、20+ 类目 skills 的规模也显露出功能扩张偏快、收敛不足的迹象（36,223 个开放 Issue 与之呼应）。

创新性：自我技能生成机制（从使用经验中提炼可复用技能）、跨平台"runs anywhere"设计、以及"platform adapter + skill marketplace"的生态化架构均有明显创新，绝非简单复制 Claude Code/Codex。

差异化：与同赛道项目相比，其核心差异在于"代理随使用成长"的技能习得机制和多平台网关的一体化设计；内部还提供 openclaw 迁移脚本，体现出明确的竞品替代定位。

评分依据：产品理念清晰且有显著创新，功能取舍得当，差异化明确；但生态膨胀导致部分功能冗余，故落在 9–10 档下沿，按 80% 折算为 1.2 / 1.5。
