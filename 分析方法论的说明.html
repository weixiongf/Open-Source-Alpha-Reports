三种价值正交：
· 商业价值（D1–D9）回答「有人愿意付钱吗」
· D10 回答「用它的人省了/赚了多少」
· D11 回答「它给行业带来了什么」
好用但赚不到钱的项目不会因功能价值高被美化商业分，赚钱但无外部性的项目也不会被拉低评分。

三、评分标准

每维度 0–10 分，细则按六档粒度打分（细则满分 × 0% / 20% / 40% / 60% / 80% / 100%，避免伪精度）；数据缺失或维度不适用时标记 N/A，从满分中剔除后等比缩放，禁止打 0 分充数。

分数区间档位含义
9–10卓越远超行业平均，构成显著商业优势
7–8良好高于平均，无明显短板
5–6一般达到行业平均，有改进空间
3–4较弱低于平均，构成商业化障碍
1–2严重缺陷存在根本性问题，难以商业化
0极端缺陷已评估且确认该项完全不成立
N/A不适用/无法评估数据缺失或维度不适用，不计入评分

综合评分 = (D1×13% + D2×14% + D3×11% + D4×18% + D5×12% + D6×7% + D7×8% + D8×7% + D9×10%) × 10 − 用户利益扣分

四、扣分标准

  • 短板敏感：任一 D1–D9 加权维度 ≤ 4 分即标记为「商业化硬伤」，报告中必须重点呈现（这就是「两大硬伤」章节的由来）。
  • 用户利益侵害扣分：专项检查覆盖代码行为域与运营/产品模式域（恶意挖矿、后门、凭据窃取、数据外传、过度采集、暗扣费、暗黑模式、虚假宣传等）。发现侵害时按严重程度扣分——严重每项 -5 分、中度每项 -3 分、轻微每项 -1 分，累计封顶 10 分；无侵害时报告完全无痕。
  • 一票否决：以下任一情况等级直接判 D——① D6 法律合规 ≤ 3 分（根本性法律障碍）；② D8.4 项目可持续性 ≤ 1 分（项目已停滞/废弃）；③ D4.1 协议严重限制商业使用（≤ 0.5 分，如无协议或严重限制性协议）。年龄 < 90 天且保持活跃的新项目豁免 D8.4 否决（无历史 ≠ 停滞）。
  • 数据信号归因纪律：数据低 ≠ 技术差。数据驱动的低分（社区指标、活动数据等）评分前先做归因——「太新 / 未推广 / 语言·地域壁垒 / 单人维护 / 工具型低互动 / 垂直小众」等良性归因不改分，但报告中禁止把数据低写成技术差、质量差。
