【注意】本章节为降级概要（安装指南草稿缺失），要点来自 D9 评分卡：

  • UX 被刻意抽离到 Skill 层（README: skill/ the Codex Skill (the real UX layer)），日常操作压缩为对 Codex 说一句话，用户无需理解 MCP/OAuth/tunnel/port
  • 示例文件数为 0，缺少可模仿的模板项目；提供了 docs/troubleshooting.md 与 c2c doctor/logs 自诊断能力
  • 首次使用存在不可消除的人工断点：ChatGPT 登录、验证码/2FA、连接器配对、可选 Cloudflare 授权，故首体验落在 30 分钟档而非 10 分钟档
  • 上手便利性高度依赖前置条件"用户已有一个可执行安装的编码 Agent（Codex）"，无 Codex 时需回落到需 Node 环境与构建的手动路径

D2.1 产品设计与创新性 — 1.2 / 1.5

判断依据

  • 产品理念清晰：一句话定位明确——"ChatGPT thinks. Codex works."，即让 ChatGPT 作为「规划大脑」，同时保留 Codex 作为「执行外壳」。解决的问题是 ChatGPT 侧缺执行环境、Codex 侧缺高质量规划模型，通过把本地 Codex 能力封装为 MCP 服务并接入 ChatGPT 连接器来打通两端。
  • 功能设计围绕核心场景：代码模块（bridge/mcp/auth/tunnel/pairing/workspace/execution/session）完整覆盖了「暴露本地工作区 → 鉴权配对 → 公网可达 → 工具调用 → 执行留痕」这一条主链路，无明显堆砌；skill/SKILL.md 还提供了与 Agent 协作的技能描述，属于对场景的细化取舍。
  • 创新性中等偏上：本质是把两个成熟产品（ChatGPT 连接器机制 + Codex CLI）用 MCP + OAuth + Cloudflare 隧道做集成式创新，属于「模式创新」而非底层技术创新；但这种「反向桥接」（把本地 Agent Harness 反过来喂给云端大模型当工具集）在同类中并不常见。
  • 差异化点：自带 OAuth 2.x + PKCE 授权服务器、配对码机制、cloudflared 快速/命名隧道双模式、工作区沙箱白名单自动改写 Codex TOML 配置，这些都是「开箱即用」取向的差异化设计，比单纯转发 MCP 请求的项目更完整。

未达 9–10 档的原因：创新建立在既有生态组件之上，缺少独到的算法或体验层突破；产品形态仍绑定 ChatGPT 与 Codex 两方外部依赖。

D2.2 架构设计与工程质量 — 1.6 / 2.0

判断依据

  • 分层清晰：src/ 下按职责划分为 12 个一级模块（auth / bridge / cli / config / execution / logger / mcp / pairing / process / session / tunnel / workspace），bridge（HTTP/生命周期）与 mcp（协议工具层）分离、tunnel（可达性）与 auth（鉴权）分离，符合本地代理服务的典型分层范式。
  • 模块解耦较好：依赖方向基本单向——cli → bridge/process，bridge → auth/workspace/pairing，底层 config/logger 被广泛复用且无反向依赖；tunnel/provider.ts 定义了 TunnelProvider 抽象并配 cloudflared / cloudflared-named 两种实现，抽象层次恰当，未过度设计。

4.3 结论与风险提示

综合判断：5.2/10（一般偏弱）。 协议层面是满分（MIT 完全放开所有变现路径），但商业实质层面存在结构性矛盾——该项目的核心价值主张是"省钱"而非"创造新的付费理由"，免费版即完整版，且目标客群正是价格敏感度最高的个人开发者。五项商业可行模式（Open Core/SaaS/双协议/专业服务/插件市场）中四项被架构或产品定位直接排除。

三条决定性风险：

  1. 平台依附与合规悬崖：产品依赖 ChatGPT 网页版订阅额度（Plus/Pro）与 Computer Use 通道，属非官方集成，README 明示"Not affiliated with or endorsed by OpenAI"。任何商业化（尤其收费的托管/代管）都会显著抬高被平台封禁、ToS 追责的风险，构成对变现可行性的根本性约束（法律合规细节见 D6.1，本维度仅评估其对商业路径的压制）。
  2. 可替代性风险：OpenAI 官方 Codex 与 ChatGPT 的原生协同属其路线图内能力，一旦官方打通，本项目价值即刻归零，无技术护城河（8875 行 TypeScript、~10 名贡献者、v0.1.x、无 CI）。
  3. 成熟度过早：2026-08-28 创建，至最近推送仅约 2 周，3 个 patch 版本（v0.1.0–v0.1.2），未进入 PMF 验证阶段，尚不具备讨论收入模型的时间基础。

可探索的弱路径（若强行商业化）：面向非技术用户的付费托管/代维套餐（$5–15/月）、面向小团队的稳定隧道 + 审计合规增值包、以及 Sponsors/OpenCollective 赞助。三者合计天花板有限，建议在 D4 维度上按"潜在但高度不确定"处理。

D6.1 协议合规性（3.0/3，9–10 档） LICENSE 文件为标准 MIT 全文，版权人标注为 "codex-with-chatgpt contributors"，正文无任何删改或附加限制条款。package.json 中 SPDX 标识 MIT 与 LICENSE 文件一致，README 未见其他协议声明冲突。MIT 属完全宽松许可，明确授予商用、修改、分发、再许可与销售权，不构成 copyleft 传染，不存在 Commons Clause、BUSL、SSPL 等限制商业使用的附加条款。对本项目而言，采用 MIT 意味着无法通过版权许可本身构建排他性壁垒（该影响已在 D4.1 层面讨论，本细则不重复扣分），但从法律合规角度无任何障碍，商业路径在协议层面完全通畅。
