1. 部署方案概要

本项目不是可独立运行的应用，而是「商业游戏 + 引擎补丁 + 本地控制器 + 大模型 Agent」四段式实验装置。运行链路（引自 README）：

flowchart LR
    A[Codex / GPT-6 Astra] -->|JavaScript plan| B[Local MCP server]
    B -->|TCP on 127.0.0.1:27182| C[Custom SourcePauseTool]
    C -->|Play N ticks, then pause| D[Portal]
    D -->|Screenshot + position + facing| C
    C --> B
    B --> A

需要准备的组件（README 明确列出，仓库不包含游戏本体）：

组件 所在目录 / 来源 说明
Portal 游戏本体 自备 README："Game files are not included; you'll need your own copy of Portal."
自定义 SourcePauseTool spt/（上游 + 本仓库补丁） 保留上游 license 与 NOTICE，需应用本仓库改动

2. 环境要求

  • 操作系统：Windows（README："Run it yourself — the tested Windows setup"），无 macOS/Linux 支持证据。
  • 运行时：Node.js（controller/package.json 声明 "type": "module"；无第三方 npm 依赖字段，运行时依赖自包含程度较好）。
  • 游戏侧：需自备 Portal 副本，并具备向游戏目录投放 SPT loader / 调整游戏设置的能力。
  • 模型侧：需外部大模型服务访问能力（原 run 耗时约 23 小时 43 分钟，含容量中断与等待）。

3. 技术要点

  • 控制器与打了补丁的 SourcePauseTool 之间通过本地 TCP 127.0.0.1:27182 通信；链路语义为「推进 N 个 tick 后暂停」，暂停期间 Agent 读取截图、玩家位置与相机朝向并决定下一步输入。
  • MCP server 位于本地，负责 Agent 与游戏之间的转译；Agent 侧产出为 JavaScript 计划。
  • 仓库未提供 Dockerfile、docker-compose、Helm Chart、CI workflow，也无一键安装脚本；controller/package.json 中仅有的两条脚本为测试/手动用途，非安装步骤：
  • "manual": "node scripts/manual-test.mjs"
  • "test": "node index.test.mjs"
  • 部署顺序本质上是：准备游戏 → 应用 SPT 改动 → 投放 loader 与游戏配置 → 启动本地 MCP server/控制器 → 配置 Agent 指令与模型凭据 → 运行并观察会话。

4. 结论

该方案涉及商业游戏授权、引擎侧补丁、本地 TCP 服务、外部大模型账号四类外部依赖，且仅覆盖 Windows，缺少容器化与一键脚本，非开发人员无法独立完成部署；对使用者存在明显的领域知识门槛（Source 引擎 tick/暂停机制、SPT、MCP 协议、Agent 提示词工程）。
