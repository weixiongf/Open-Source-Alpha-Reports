1.3 一句话定位

dlssg_for_sm86 是一个游戏图形增强代理工具，适用于 PC 游戏（数字娱乐），主要面向 RTX 30 系列显卡的 PC 玩家，用于在 Ampere 架构 GPU 上启用 NVIDIA DLSS 帧生成以提升帧率。

二、安装部署与使用指南

上手难度等级：🟡 中等（D9 = 6.0 / 10） —— 面向有基本技术基础的 Windows 游戏玩家：无需开发经验、无需编译、无需 CUDA Toolkit / Python，但需要能定位游戏渲染 EXE 目录、理解 DLL 代理机制与驱动版本要求，并能自行处理杀软误报与 SmartScreen 提示。

一、环境前提（硬性）

  • 操作系统与游戏：Windows 10/11 x64，游戏须为 D3D12。
  • GPU：RTX 30 系列（SM86）。README 记录 3080 Ti 上完成整套离线基准、3070 上做开发验证。
  • 驱动：带 NGX / NVAPI / CUDA 接口的 NVIDIA 驱动，README 实测 591.86 与 610.74 可用；cubin 需约 R580+ 驱动，更旧的驱动自动回退 PTX（仅首帧多一次 JIT）。
  • 明确不需要 CUDA Toolkit，不需要 Python。

二、部署步骤（摘自 README「安装与升级」）

  1. 完全退出游戏。
  2. 进入游戏的渲染 EXE 目录（如《黑神话：悟空》为 ...\b1\Binaries\Win64\）。
  3. 将 version.dll 与 dlssg_sm86.ini 复制进去；该目录已有 version.dll 时先备份原文件。少数游戏不加载 version.dll，改用发布包 alternatives\ 目录下的其它代理名（按游戏实际加载的 DLL 选一个，如 winmm.dll / dxgi.dll / dbghelp.dll 等）。
  4. 启动游戏，在图形设置中开启 DLSS 帧生成，选 2X / 3X / 4X（310.9 版且游戏支持时可至 6X）。
  5. 升级：退出游戏后用新版 version.dll 覆盖即可，dlssg_sm86.ini 一般无需改动。
  6. 卸载：用备份的原 version.dll 覆盖回去（或删除），并删除 dlssg_sm86.ini。

三、最小配置

出厂 dlssg_sm86.ini 只保留两个决定性开关：

  • [FrameGeneration] Optimized：1 用最优内核（输出与原厂逐位一致），0 用原厂数值不优化。
  • [FrameGeneration] MaxGeneratedFrames：5 对应 6X、3 对应 4X，实际生成帧数由游戏请求、并钳到运行库上限。

其余诊断/兼容项取安全默认、不在出厂文件中，完整清单见 docs/INSTALL.md。

四、验证与排障

  • 日志写入游戏目录 dlssg_sm86\logs\（loader_<PID>.jsonl / backend_<PID>.jsonl）。默认 [Logging] Level=1 只记错误，排查时改 2 或 3。
  • 帧生成未生效时先看 backend_*.jsonl 是否有 install 且 route active=true；缺失多为驱动/运行库不匹配，会记录原因并回退原厂路径。
  • 杀软误报与签名：代理 DLL 均做代码签名，使用自签证书 CN=DLSSG for SM86 (self-signed)，SHA-1 指纹 85BA66762F851E49148D706915D09026281418E6；自签名不提供 Windows 默认信任，首次运行 SmartScreen 仍可能提示「未知发布者」，可用文件属性→数字签名或 signtool verify /pa 核对。

五、已知限制（影响首次成功体验）

  • 6X 仅当游戏自身支持（自带较新的 Streamline 帧生成插件）；仅支持 4X 的游戏无法抬到 6X，强行加帧会越界导致帧生成失效或崩溃。
  • 插帧观感依赖基础帧率：基础帧率偏低时可能出现画面破坏与边缘效应，倍率越高越明显。
  • 项目为代理 DLL 的发布包形式，无 Docker / 包管理器安装方式，无 quickstart / demo 脚本，仅覆盖 Windows x64 单一平台。

  • 痛点真实性：NVIDIA 官方将 DLSS 帧生成限制在 RTX 40 系列及以上，RTX 30 系列用户在新游戏中无法使用该功能，而帧生成对高分辨率/高画质下的帧率提升显著。README 中列出《黑神话：悟空》《赛博朋克 2077》《FH6》等实测反馈，以及 112 个开放 Issue，说明用户需求真实且活跃。属于「明确痛点」而非伪需求。

五、商业化价值判断

综合结论：这是一个"高真实需求、高用户热情、但商业价值几乎不可提取"的项目，综合评分 45.9/100，等级 C（低商业化潜力）。

支撑判断的核心事实：

（1）需求侧真实且强烈，但市场天花板被硬件切片锁死。 痛点真实明确——RTX 30 系玩家被官方限制无法使用 DLSS 帧生成，112 个开放 Issue 与 2714 stars 印证需求活跃；但市场范围仅限 Windows x64/D3D12 游戏、目标硬件为上一代 RTX 30 系，长期存量将随换代收缩。D1 得分 6.0，是本项目商业侧最高维度，但"需求真实"与"可收费"之间存在结构性断裂。

（2）变现侧被协议与用户属性双重锁死。 D4 仅 2.8/10，为九维最低。源码采用 GPLv3 强传染协议，且内嵌 NVIDIA 专有 DLL 与内核资源不随源码转授权，无法双协议或闭源衍生；无企业版/付费版设计，变现路径仅有捐赠/赞助且不可规模化，Open Core/SaaS/双协议均不可行；目标用户为游戏玩家，付费意愿极低，无免费到付费的转化触发点；无安全/合规/SLA 等增值服务设计，客单价天花板极低。

（3）法律合规构成实质性商业化阻断。 D6 仅 3.4/10。仓库无任何 LICENSE 文件（本地实测 license=NONE，GitHub API license=null），默认"保留所有权利"，第三方商业使用无法律依据，直接阻断商业化路径；项目核心功能必然依赖/再分发 NVIDIA 专有 dlssg 运行时，构成"无开源协议的高风险依赖"，涉嫌违反 NVIDIA EULA 与著作权；项目名直接使用 NVIDIA 品牌"dlssg/DLSS"字样，存在商标与专利风险点。虽未触发一票否决（D6 维度总分 3.4 > 3），但已逼近否决线。

（4）工程与企业就绪度不支持任何形式的商业运营。 D2 4.4/10、D7 3.6/10。仓库无可检出源码（total_code_lines=0、language=null），以预编译产物+文档+分版本归档形式分发；0 测试文件、0 CI workflow、无 Dockerfile、无 lint/format 配置、无 CODEOWNERS、无 LICENSE、贡献者仅 1 人；无任何企业级认证授权与权限模型（无 SSO/OAuth/LDAP/SAML、无 RBAC/ABAC），无 REST/gRPC/SDK 与 OpenTelemetry/Prometheus/Webhook 接入。
