D1.2 痛点真实性与解决程度 —— 2.0 / 2.5

考察点 评估结果
痛点真实性 明确且偏刚需。三类真实痛点：(1) Agent/开发者处理 AI 文本时，隐形 Unicode、bidi、同形空格等字符会污染下游处理链路（检索、展示、解析）；(2) C2PA/EXIF/XMP 元数据引发隐私与数据所有权关切（自有内容携带他人可追踪的溯源指纹）；(3) 数据工程师清洗 LLM 生成训练数据时需要去除统计水印干扰。README 的「行业双层模型」和对「自有内容」的权限边界声明，说明其目标场景经过仔细界定
解决完整度 较完整。三层方案：Layer A 确定性 Unicode 清理（完整）；Layer B 统计水印重写（提供 rewrite hook + 本地 Ollama/OpenAI-compatible 后端，但存在质量代价，README 明确披露残余风险）；文件层全格式元数据剥离（24 种格式，完整）。可选重型能力（CtrlRegen 像素去除、reverse-SynthID 评分）为实验性增强而非核心承诺
替代成本 有替代品但分散且体验更差。同类工具（noai-watermark、DeSynth、reverse-SynthID）多为单一供应商/单一格式/纯命令行，且无 HTTP 服务、无 Agent Skill 封装、无批量 API。用户若自建需同时组合多个工具，替代成本高

判断依据: 32 个开放 Issue 中涉及检测准确性、格式支持等用户真实反馈；90 天关闭 60 个 Issue、138 个 PR，社区交付活跃；测试占比 40.9%（10,592/25,873 行），工程化程度高，说明并非「能用就行」的自嗨项目。
