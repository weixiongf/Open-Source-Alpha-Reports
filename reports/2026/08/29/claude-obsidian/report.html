二、安装部署与使用指南

上手难度等级：🟡 中等（6.5/10） — 面向有技术基础者。开发者在 30 分钟内可完成首次跑通；非技术用户需补充基础环境知识。以下给出关键步骤，省略基础环境安装细节。

环境前置要求

  • Python 3.11 或更新（便携核心必需）
  • Bash（setup 脚本、可选扩展与 shell 测试套件）
  • Claude Code（核心交互入口，通过本地插件模式加载）
  • Obsidian（推荐，用于可视化 vault 体验；纯 Markdown 无 Obsidian 也可用）
  • Windows 注意：原生 Windows（含 Git Bash）仅支持只读检查与 dry-run，vault 写入必须使用 WSL，否则报 UNSUPPORTED_PLATFORM 错误并拒绝执行

安装产品代码

git clone https://github.com/AgriciDaniel/claude-obsidian.git
cd claude-obsidian

该 checkout 仅包含产品代码，不是你的知识 vault。项目无 Dockerfile，无第三方 pip 依赖清单，核心为自包含 Python 脚本 + skill 文件。

初始化独立 vault（两阶段安全流程）

所有 mutating 命令必须先预览 JSON plan、复制 approved_plan_sha256，再显式 --apply：

export GENERATED_AT="$(date -u +%Y-%m-%dT%H:%M:%SZ)"
export OPERATION_ID="init-reviewed"

python3 scripts/claude-obsidian.py init "$HOME/Documents/MyKnowledgeVault" \
  --generated-at "$GENERATED_AT" --operation-id "$OPERATION_ID"

审查输出的 JSON plan 并提取 approved_plan_sha256 后，应用该操作：

python3 scripts/claude-obsidian.py init "$HOME/Documents/MyKnowledgeVault" \
  --generated-at "$GENERATED_AT" --operation-id "$OPERATION_ID" \
  --approved-plan-sha256 "<sha256-from-the-plan>" --apply

已有 Obsidian vault 的用户可使用非破坏性 adopt 工作流（详见 docs/install-guide.md）。

启动与首次使用

cd "$HOME/Documents/MyKnowledgeVault"
claude --plugin-dir /absolute/path/to/claude-obsidian

在 Claude Code 中通过命名空间斜杠命令操作：

/claude-obsidian:wiki

将源材料放入 inbox/ 后执行 /claude-obsidian:wiki-ingest；用 /claude-obsidian:save 显式保存答案；用 /claude-obsidian:wiki-query 基于 vault 证据提问。

其他运维操作

  • 多 agent host（Codex/OpenCode/Gemini）：bash bin/setup-multi-agent.sh --host codex 预览，加 --apply 应用
  • 旧 vault 升级：python3 scripts/claude-obsidian.py migrate --vault /path/to/vault（同为 plan + --apply 两阶段）
  • 中断恢复：python3 scripts/claude-obsidian.py transaction recover --vault /path/to/vault
  • 健康诊断：python3 scripts/claude-obsidian.py doctor --vault PATH
  • 构建自审计产物：python3 scripts/claude-obsidian.py release build --output dist/claude-obsidian.zip

完整安装指南、Windows/WSL 专项说明及各 skill 触发短语见 docs/install-guide.md、docs/windows-wsl.md 及 skills/<name>/SKILL.md。

D2. 技术成熟度与产品质量（权重 14%）

评估背景

AgriciDaniel/claude-obsidian 是一个自组织的 AI 第二大脑项目，集成 Obsidian + Claude Code，基于 Karpathy 的 LLM Wiki 模式构建互联 Markdown 知识图谱。项目规模为 61 个 Python 文件 / 40,910 行代码，最新发布 v2.1.1，采用 MIT 许可证。以下从产品设计与工程实践双重视角逐项评估。

D2.1 产品设计与创新性（1.5/1.5）

产品理念与功能设计：项目理念清晰——"Drop any source and Claude reads, links, and files it into one connected knowledge graph"，围绕"捕获→组织→检索→维护"四大核心场景设计功能模块：capture.py（离线优先捕获）、wiki-ingest/wiki-fold skills（组织）、wiki-query/wiki-retrieve skills（检索）、wiki-lint（维护），信息架构合理且无冗余堆砌。

创新性与差异化：相比同类 AI 笔记工具，本项目有三点显著差异化： 1. 事务性安全设计：核心代码实现操作级保险库事务系统（transaction.py），提供多文件原子更新、确定性回滚/恢复、前置条件哈希验证——将数据库事务概念引入 Markdown 知识库管理，在同类工具中罕见； 2. Karpathy LLM Wiki 模式落地：基于 LLM Wiki 模式构建 provenance 账本（ledgers.py），为每条知识提供可追溯的来源与声明溯源链； 3. 多方法论内建：同时支持 LYT、PARA、Zettelkasten 三种知识管理方法论模式（skills/wiki-mode/templates/），用户可选择而非被单一模式绑定。

评分依据：产品理念清晰且有显著技术创新，功能设计精巧围绕核心场景，差异化明显。判定 9-10 档（100%）。

D2.2 架构设计与工程质量（1.6/2.0）

架构合理性：claude_obsidian/ 包内 20+ 模块职责高度单一，依赖方向正确——底层工具模块（paths、json_utils、url_safety）无上层依赖，被 transaction、capture、ledgers 等中层模块复用，顶层 cli.py 统一调度。分层遵循"基础设施→领域服务→接口层"的清晰范式。

模块解耦与抽象：模块间通过数据类（VaultSelection、LockRecord、URLSafetyIssue）和契约接口（contracts.py、gates.py）解耦；release.py 采用策略模式实现内容安全扫描，checkpoint.py 以状态机（pending→final）管理检查点生命周期，抽象层次恰当。

复刻难度：项目涉及事务日志、符号链接/TOCTOU 防护、确定性可复现构建、Unicode 路径归一化、Git 对象级操作等高级系统编程主题，领域知识门槛高，复刻难度大，构成技术护城河。

技术债：存在明显技术债迹象——transaction.py 约 4,000 行、cli.py 约 1,000 行、checkpoint.py 单函数约 570 行；paths.py 的 _strict_json_loads 与 json_utils.py 功能重复；mode_config.py 两个验证函数存在复制代码。虽不影响架构整体合理性，但尚未达到"几乎无技术债"标准。

评分依据：架构优秀、模块解耦充分、抽象恰当、复刻难度高；但存在函数过长和少量重复代码。判定 7-8 档（80%）。

D2.3 代码整洁性与规范性（0.8/1.0）

命名与注释：命名高度一致且富有语义（如 _safe_vault_path、resolve_vault_root、TransactionConflict），符合 Python 惯例；注释质量优秀——legacy_lock.py 注释清晰解释平台兼容设计决策，lint_engine.py 文档字符串详尽，url_safety.py 对检测逻辑有完整说明。
