部署方案概要

  • 站点本体：Astro 静态构建，产物在 dist/，可由任意静态托管承载。
  • 自动化部署：仓库内 CI 工作流共 3 个（deploy.yml、validate.yml、via-x-guard.yml），deploy.yml 负责部署流程。
  • 边缘/代理层：pnpm deploy:proxy 通过 Wrangler 部署 workers/t/wrangler.jsonc（Cloudflare Workers 方向），需自备 Cloudflare 相关凭据。
  • 外部服务：读写 API 位于 https://api.botdirectory.ai，该服务不在本仓库的安装链路内；自建站点时 API 侧需另行处理。
  • 配置入口：品牌字符串、URL 与开关集中在 src/config.ts；集成（颜色 + 认证）、赞助商、推广等数据在 data/ 目录。

逐项分析

D1.1 目标市场规模与增长性（1.5 / 2.5）

项目解决的问题是"Agent 提示词的发现与分发"。需区分两层市场：底层 AI Agent 工具/服务市场处于爆发增长期（量级可达百亿美元级），但本项目直接占据的"提示词目录/发现"细分，本质是内容聚合站点，可触达市场规模显著更小。其变现面（站点赞助位 + newsletter）对应的是"面向 AI/开发者受众的赞助投放"，属千万至亿美元量级的细分。

增长趋势明确为正：topics 中 agents、ai-agents、llm、automation 均处于高速扩张赛道，项目创建于 2026-08-17 且 90 天内产生 311 个 PR，说明赛道动能充足。但"目录本身"的独立市场规模与增速不能等同于底层 Agent 市场。

说明：外部市场规模数据不可用，上述为按项目类型/行业类别的量级估算，未经外部数据验证，置信度低；未引用任何具体外部数字。

D1.2 痛点真实性与解决程度（1.5 / 2.5）

痛点真实性：Agent 提示词的确散落在 X 长贴、GitHub awesome-list、Reddit 与各家官方 prompt library 中，检索与筛选存在摩擦，但该摩擦属于"提效"而非"非用不可"——不用该目录，用户仍可通过手工收集、上游官方库或同类聚合站完成同一任务，替代成本低。

供给端证据强：仓库含 653 个 bots/*.md 提示词文件，90 天内 311 个 PR、44 位贡献者，说明"贡献提示词"这一行为有真实意愿。但这是供给侧热情，README 中未见任何付费墙、定价或付费用户数据，需求端付费意愿无证据。

解决完整度：目录 + 一键 "Add to Grok Bot" + POST /api/bots + 公开读 API + updates.json 增量 feed + newsletter 已构成较完整的"发现→安装→订阅"闭环，但不含执行/托管能力，无法把用户锁定在自身平台，属于"半程方案"。

综上：痛点成立但非刚需，方案在其窄边界内较完整，替代品充分 → 5–6 档。

D1.3 市场时机判断（1.6 档 80%）

时机正面：项目创建于 2026-08，处于 Grok Bot / Rakazo 等 Agent 平台生态的极早期，尚无垄断性目录品牌成型；README 已直接对接平台官方分享链接（grok_share_url、x.ai/bot/…），卡位准确。

风险同样明确：(1) 平台原生替代风险——xAI、Rakazo 等平台方有能力原生内置提示词库，一旦成真，第三方目录价值被大幅稀释；(2) 历史先例警示——2022–2023 年 PromptBase 等提示词交易/市场类项目未能规模化变现，提示该细分存在"流量有、付费难"的结构性问题；(3) 目录型产品的壁垒主要是内容存量与 SEO，容易被镜像与复制。

综合：处于成长期早期、有先行者但格局未定，同时带有明确的平台依赖与历史包袱 → 7–8 档。

D1.4 应用场景广度（2.0 / 2.5）

横跨职能广泛：bots/ 目录已覆盖营销投放（ad-creative-generator、ad-pacing-digest）、SEO/AEO（autonomous-seo-engineer、aeo-content-autopilot）、财务（bookkeeping-auditor、accountingbot）、招聘（applicant-screener）、视频内容生产（ai-video-editor、ai-music-video-maker）、客服与运营（approval-queue-triage、appointment-slot-watcher）等，属横向通用型内容资产。

可延展性中等偏强：GET /api/bots、bots.json 全量 feed、updates.json 增量 feed 使目录可被其他 Agent/工具当作数据源消费（README 明确提供"recurring scout"用法），具备向"Agent 能力市场/索引层"延展的可能。

但需注意：其广度来源于贡献者批量提交的内容广度，而非核心能力可迁移——项目自身无技术内核，行业覆盖随时可被复制。综合判为 7–8 档。

维度结论

D1 得分 6.75 / 10。项目站在一个高速增长的赛道上，且已用 653 个 Prompt、44 位贡献者、90 天 311 个 PR 证明"内容供给"侧的社区拉力；场景横向覆盖营销、财务、SEO、HR、内容生产等多个职能，通用性良好。但两个结构性短板压制了商业机会上限：一是市场层级偏小——本质是内容聚合目录，可变现面（赞助位 + newsletter）天花板有限；二是需求刚性与付费意愿未验证——提示词发现属"提效型"需求，替代品充足（官方 prompt library、awesome-list、X/Reddit），且历史同类项目（PromptBase 等）未能规模化变现。叠加平台方（xAI/Rakazo）可原生内置目录的平台依赖风险，D1 判定为"机会真实但天花板不高、且需要尽快验证付费侧"。

优势：月增约 199 star、Fork 率 42.3%、44 名贡献者与 311 个 PR（约 30 天内），贡献漏斗（Fork→PR 的 2 分钟流程、X 提及机器人自动开 PR、CI 校验）设计成熟，把「提交门槛」压到极低，社区参与量能在同类目录项目中相当突出；MIT 许可 + 公开读写 API/JSON Feed 也为外部 agent 消费预留了集成面。

风险：① 所有活跃度信号均来自不足 1 个月的观测窗，无法区分产品力与发布期营销脉冲，Watchers 仅 1 更暗示关注度并未沉淀为长期黏性；② 极高 PR 量部分由自动化机器人产生，社区规模需打折扣解读；③ Issue 追踪器近乎弃用（90 天关闭 0），维护者响应能力无实证；④ 第三方生态完全空白——无插件、无衍生项目、无外部教程、无企业采用背书；⑤ 与 Grok Bot/Rakazo 的关联目前仅为链接格式层面的软对接，未获平台方背书。

对商业化的含义：本项目可作为「AI agent 提示词分发/曝光渠道」的低成本流量入口，但社区势能尚未转化为可验证的客户池或生态护城河。D3 得分为 6.2，处于"一般"区间偏上——量能指标亮眼，生态与品牌指标的实质空白拉低了整体。建议后续补采「近 90 天 Star 增量（真实值）、贡献者组织归属、外部教程/媒体提及」以提升置信度。
