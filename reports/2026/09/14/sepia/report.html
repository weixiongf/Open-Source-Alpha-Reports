考察点 判断

D1.2 痛点真实性与解决程度（满分 2.5）

考察点 判断
痛点真实性 真实但非"非用不可"。LLM 生成文本同质化、被读者/平台识别为 AI 写作，是小说作者、内容运营、技术写作者的真实困扰，且已有付费产品验证过付费意愿；但对多数用户仍偏"锦上添花"
解决完整度 相对完整。README 明确了三层 pass（叙事架构 / 语篇流 / 表层风格）、30 项诊断 rubric、按模型指纹库、五个文档类型专用规则文件、中英双语节奏校准，并以 behavioral-eval CI 做行为回归；比市面上"换词换句式"的 humanizer 方法论厚度明显更高。但本质是规则/提示层方案，最终输出质量仍取决于执行模型，无内置的"检测器反馈闭环"保证效果
替代成本 替代品众多：直接提示模型"写得像人"、手工编辑、商业 humanizer、其他 humanizer 类 Skill。但同类替代品普遍停留在表层风格层，项目自论证（LAMP 条件下改写表层风格后检测率仅从 95.5% 降至 93.9%）说明其切入的架构层确有差异化

小分：2.0 / 2.5（80%，对应 7–8 档）

依据：痛点明确、方案较完整且论证有据（引用 61,608 篇故事的前沿模型检测研究），替代品存在但体验/深度更差，符合 7–8 档描述。未达 9–10 档的原因：一是它不是"非用不可"的行业刚需，二是缺少效果可验证的产品化闭环，三是素材中仅有 2 个开放 Issue，缺少可直接佐证用户痛点强度的 issue 文本证据。

D5.2 技术壁垒与网络效应（3 分）

本节仅评估壁垒的商业防御效果；"从零复刻的工程难度"已在 D2.2 计分，此处不重复计分。

技术壁垒： - 资产构成是 markdown 技能文件 + 37 份 research/ 摘要 + 30 特征诊断 rubric + per-model 指纹 + 仅 916 行 Python / 2 个源文件。全部以 MIT 协议开源，无专利、无算法黑盒、无专属数据集——任何人可整目录复制。 - 真正的"半壁垒"是知识密度与维护节奏：把 13+ 篇一手论文（StoryScope、LAMP、Measuring AI Slop、Reinhart et al.、NarraBench 等）转译为可执行规则，并针对各家厂商公开 prompting guide 建立指纹（README 明确记录"未发布指南的厂商记为 consulted, not guessed"）。这种证据基座需要持续文献投入，复制成本高于抄一份 prompt，但不构成法律或技术锁定。 - 工程侧有真实质量投入：behavioral-eval.yml + version-consistency.yml 两条 CI、测试 547 行（test_ratio 0.597）、90 天内 10 次发版、51 个 PR。这形成迭代速度壁垒，而非技术壁垒。

D5.3 切换成本与用户粘性（2 分）

迁移成本：极低。安装与卸载均为单条命令（npx skills add / remove、claude plugin install / uninstall、codex plugin add/remove、grok plugin install/uninstall、agy plugin install/uninstall）。技能本身为纯 markdown，不产生用户数据、不写数据库、无云端账户（README 明确 "You can use sepia for free without an account"）——因此不存在数据迁移成本。

深度集成：技能以自然语言协议注入 agent 上下文，用户无需改业务代码、无需 SDK 集成、无需部署。唯一略深的形态是 project scope（把 skills/sepia/ 提交为 .agents/skills/sepia 或 .claude/skills/sepia），此时技能文件随仓库版本化，构成轻度仓库级依赖；但删除该目录即可回退。

习惯锁定：存在习惯性粘性——用户会形成固定的 4 个操作入口（write / review / refactor / recreate）与 /sepia-hemingway 的使用肌肉记忆，重度用户还可能自建 domain/voice 规则引用；但这些都是习得性而非结构性依赖，竞品（如 unslop）可在数分钟内替换。

得分：0.8 / 2（3–4 档 → 40%）——迁移成本低、可即插即用即走，仅有习惯层面的部分粘性，缺少数据/配置/流程锁定。未打到 1–2 档，因为 project-scope 版本化集成与自建 voice/domain 规则确实构成了少量重配成本。
